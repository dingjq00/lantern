核心理念

用户面对一个输入框，用自然语言查询、分析、操作企业数据。 背后是 LLM 路由 + MCP 确定性执行 + ReAct 推理循环 的混合架构 —— AI 负责理解意图和跨域推理，MCP 工具负责确定性的数据获取和聚合。 不走 Text-to-SQL 路线，而是通过声明式工具描述（YAML）让 AI "选对工具、传对参数"。

6 层 Context 架构

静态内容在前（LLM cache friendly），动态内容在后。

1 System Prompt 角色定义、基本行为规则 静态
2 Rules 架构原则、禁止事项（底线约束） 静态
3 Task Instructions 5 步结构化思考模板（ToolGT / Step-Back / Reflexion） 静态
4 Few-shot Examples 示例对话 — AI 从模式延续比从规则学习更稳定 静态
5 Dynamic Context 工具 YAML 描述、术语注入、领域模型、会话记忆 动态
6 User Input 当前查询 + Concept Resolver 术语提示 动态

核心设计原则

#1 MCP 是动作，AI 是能力
确定性逻辑 MCP 做（ID 解析、聚合），分析推理 AI 做（意图判断、跨域编排）
#2 Resolver 模式（独创）
AI 传名称不传 ID，MCP 内部 Resolver 自动模糊匹配。AI 决策空间从"30 工具 + ID 解析"缩小到"30 工具 + 传字符串"
#3 上层泛化，下层具象
Prompt / Instructions 是方法论层，必须跨系统通用。YAML 是配置层，可以写具体业务
#4 Few-shot > 规则
AI 从示例延续模式比从规则学习更稳定。规则精简 44% 不退化
#5 预计算是辅助不是替代
Data Digest 预算统计引导 AI 引用正确数字，但原始数据必须保留
#6 上下文情绪色彩
正向环境出自信推理，防御环境（如 _truncated）出犹豫输出。注入到上下文的任何标记都要审视其情绪影响
#7 Handler 决定 AI 能力上限
AI 再聪明也分析不了 Handler 没返回的字段。数据完整性在 Handler 层保证
#8 确定性逻辑不靠 AI 判断
术语匹配、数数、周期计算都在 Router / Digest 层预处理，不留给 AI

接入新系统的标准流程

  1. systems.ts 注册 — 加一条系统元数据（label / scope / domainModel / 术语表 / 领域公式）
  2. mcp-server/src/jmix-api.ts — createJmixClient(config) 创建新系统的 API 客户端实例
  3. mcp-server/src/handlers/ — 编写 Handler（数据获取 + Resolver + 聚合）
  4. skills/<system>/ — 编写 YAML 工具声明（when_to_use 是最重要的字段）
  5. few-shot-examples.json — 补充 1-2 个新系统示例
  6. data/platform-test-cases.ts — 加 L1 路由消歧题 + L2 跨系统题 + L3 单系统题
  7. 跑 Benchmark 验证 — npx tsx scripts/benchmark-platform.ts

MES 系统从零到全栈落地（10 工具 + Benchmark 通过）仅用一个下午完成，验证了这套标准流程的可复制性。
