真实实施 · 你的战场

JSY（南厂酿酒车间）是 Lantern 首个真实落地项目，对接的是现场真实运行的白酒酿造 MES 系统。数据是生产数据，凭据是真实账号——本手册全程讲这个。

⚠ 真实环境 ≠ 联调环境，三条心态先立住
  • 上帝口令禁用：联调旁路 JSY_GOD_TOKEN=1（口令 oiiaioiiiai）绝不能用在真实环境，必须用真实工号/密码登录。
  • 生产数据要敬畏：你查的是车间真实窖池/曲房数据。Lantern 只接查询、永不接写操作（见 第 5 节红线）。
  • 慢就是快：先把一个最简单的工具（jsy.ferment.room.profile）用真实编号跑通，再铺开。链路一通，其余都是复制。

Next.js Web/API → Brain（意图路由 + ReAct 循环 + 数据摘要 + 结果呈现）

改完 handler 重启 lantern 即生效，不必 build。改 ENABLED_SYSTEMS 前端与 mcp-server 两边都要重启。

1环境搭建（全新机器，约 15 分钟）

1

装 Node.js + 拉代码，切到 JSY 分支

需要 Node.js 18+。JSY 全部代码在 feat/p0-platform 分支（不在 main）。

git clone https://github.com/dingjq00/lantern.git
cd lantern
git checkout feat/p0-platform
2

装依赖（根目录 + mcp-server 两处）

npm install                      # 根目录（Next.js 前端 + Brain）
cd mcp-server && npm install     # MCP server（工具执行层）
cd ..
3

配置环境变量 — 务必先 cp，别手建

cp .env.example .env.local
✖ 不要手建只含 JSY 块的 .env.local

手建会漏掉 LLM_API_KEY（漏了 → AI 大脑直接瘫）和 TOOLS_DIR=./skills（漏了 → 退回默认 ./tools 空目录，工具一个都加载不出）。必须从 .env.example 拷一份再改。

然后编辑 .env.local，改这几项：

# ① LLM —— 必填，否则 brain 不工作（DeepSeek 官方 key）
LLM_API_KEY=<你的 DeepSeek key>

# ② 只挂 JSY —— 不挂那三套测试系统，免得 LLM 看到连不上的工具浪费推理轮次
ENABLED_SYSTEMS=jsy

# ③ JSY 真实后端（IIS 部署，向现场要地址/端口/账号）
JSY_API_BASE_URL=http://<JSY_HOST>:<PORT>
JSY_USERNAME=<真实工号>
JSY_PASSWORD=<真实密码>

# ④ 联调旁路 —— 真实环境保持注释/不要开！
# JSY_GOD_TOKEN=1
提示

cp 来的模板已含 TOOLS_DIR=./skills，别删。ENABLED_SYSTEMS 改完后启动才生效——前端和 mcp-server 都从这个变量读。

4

类型检查（可选但建议）

cd mcp-server && npm run build   # 仅类型检查；过了说明 4 个 handler 类型没问题
cd ..
⚠ 运行机制（容易踩的认知坑）

Lantern 运行时用 npx tsx mcp-server/src/index.ts 直接跑 TS 源码（见 app/api/chat/route.ts），不从 dist/ 跑。所以：改完 handler 不需要 build，只要重启 lantern 就生效；build 只是提前抓类型错 + 让独立 smoke test（node dist/index.js）能用。

5

启动

npm run dev   # 访问 http://localhost:3000

MCP server 由前端按需以 stdio 自动拉起，无需单独启动。

2连通性分层验证（出问题时按顺序逐层排）

真实环境第一次连接，从下往上逐层确认，每层独立验证，别一上来就跑前端。

1

网络层 — 能不能 curl 到 JSY

先打公开接口 /PublicKey（不需要 token），确认地址/端口/网络通：

curl http://<JSY_HOST>:<PORT>/PublicKey
2

登录层 — 真实账号能不能拿到 token

curl -X POST http://<JSY_HOST>:<PORT>/Login \
  -H "Content-Type: application/json" \
  -d '{"UserName":"<工号>","Password":"<密码>","VerifiCationCode":""}'

期望返回 { "Code": 200, "Data": { "Token": "..." } }。

⚠ 字段拼写别"修正"

服务端字段 VerifiCationCode（C 大写，拼写就是这样）、UserName 都是 PascalCase，大小写敏感，写错后端拿不到值。

3

工具层 — 单个 MCP 工具能不能跑通

最简单的 smoke test 是 jsy.ferment.room.profile（单参数、单 endpoint、易核对）：

# 方式一：用项目脚本（推荐）
npx tsx scripts/jsy/test-tool.ts jsy.ferment.room.profile '{"roomId":"<现场真实曲房编号>"}'

# 方式二：直接走 MCP stdio
echo '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"jsy.ferment.room.profile","arguments":{"roomId":"<编号>"}}}' \
  | node mcp-server/dist/index.js

走通这一个，说明 token 链路 + 解包 + 路由 全对了。

4

平台层 — 前端自然语言问一句

打开 http://localhost:3000，问："X 号曲房现在什么状态？" 看是否正确路由到 jsy.ferment.room.profile 并返回真实数据。

✓ 第一阶段验收清单
  • /PublicKey 能 curl 通（网络/地址对）
  • /Login 用真实账号返回 Code:200 + Token
  • 至少一个 MCP 工具用真实编号跑出 JSON
  • 前端自然语言提问能路由到正确工具并返回数据

3P0 四工具真实数据验收

逐个用现场真实编号跑通这四个工具，重点核对三件事：数据对不对、字段全不全、返回大不大。

工具典型问法关键入参
jsy.ferment.room.profile"X 号曲房什么状态"roomId（必填）
jsy.ferment.order.search"X 号曲房的发酵工单"roomId / 日期范围 / 分页
jsy.pit.lifecycle"X 号窖池履历 / PITN 工单"unitCode + 各 include* 开关
jsy.hut.inventory.search"曲库存 / 出入仓记录"mode + 按模式传参
⚠ 联调期两个要现场确认的点
  • 分页字段拼写：jsy-api.ts 已兼容 rows|list|data 与 total|totalCount 几种可能。第一次联调打开网络面板看实际返回字段，在 JsyPageResult 类型里固定下来。
  • 返回体过大：P0 工具默认透传不裁剪。若某工具返回 >50KB，在 handler 里裁剪——去掉下拉框选项字段（Workshops/UnitOptions 等）和曲线原始点位，保留时间轴 + 数量 + 状态 + 业务标识。
响应码与 EAM 不同

JSY 响应包装 { Code, Msg, Data }，Code = 200 才是成功（不是 0！），-1 失败、0 未知。jsy-api.ts 已处理，新增工具用 jsyPost() 即可。

4扩展 P1–P3 工具

P0 跑稳后，按 docs/jsy-tool-plan.md 的 P1 → P2 → P3 顺序加工具，那里已经把每个工具的 endpoint 映射 / 入参草图 / when_to_use 写好了。新增一个工具三步走：

1

写 handler

复制 mcp-server/src/handlers/jsy/_TEMPLATE.ts.example 改名 + 改业务参数 + 改 body 字段映射（服务端字段保持 PascalCase）。

2

写 skill yaml

在 skills/jsy/ 新建同名 .yaml，参照 pit-lifecycle.yaml。写清 description / when_to_use（越具体越帮 LLM 路由）/ when_not_to_use（跟其他工具的边界）。

3

注册到 index.ts + 验证

# mcp-server/src/index.ts 三处：顶部 import、register 区调用、末尾日志 +1
npm run build                                  # 类型过
npx tsx scripts/jsy/test-tool.ts jsy.xxx '{...}'  # 跑通

最后把新业务术语补进 lib/systems.ts 的 SYSTEM_REGISTRY.jsy.businessGlossary。

5红线与上线注意

✖ 四条红线（违反则 review 不过 / 真实环境出事）
  • 写操作完全不接。前缀为 Save/Delete/Create/Add/Update/Edit/Modify/Set/Transition/Remove/Insert/Confirm/Approve/Submit/Lock/Reset/Clear… 的 endpoint 一律跳过。Lantern 是 NL 查询平台，误调写操作（删车间/改班组/insert 错数据）代价远高于查询，且 MCP 直调绕过了前端业务校验。
  • 上帝口令不上生产。JSY_GOD_TOKEN=1 / 口令 oiiaioiiiai 仅本机联调用，真实环境必须真实账号登录，且绝不提交进 git。
  • 服务端字段 PascalCase 不要"修正"。Newtonsoft.Json 大小写敏感。
  • 响应 Code=200 才是成功，不是 0。
✓ 真实环境上线前自检
  • .env.local 里 JSY_GOD_TOKEN 已注释/删除，用的是真实账号
  • 没有任何真实凭据/token 被写进代码、prompt、文档或提交进 git
  • 所有 jsy 工具都是查询类，无写操作
  • 大返回体工具已做字段裁剪，分页字段已在 JsyPageResult 固定
  • 用现场真实编号验证过路由准确性与数据正确性

附录 C · 排错速查

现象含义 / 处理
工具加载不出 / 一个都没有多半 TOOLS_DIR 漏了或 .env.local 手建。改用 cp .env.example，确认含 TOOLS_DIR=./skills
HTTP 401 Unauthorizedtoken 缺失/无效（错的 token、被踢）。jsy-api.ts 会自动重登一次
HTTP 402 PaymentRequiredtoken 超时（JWT exp 过期），服务端用 402 表达，会自动重登
HTTP 400并发限制（DistributeException）
HTTP 200 但 Code:-1业务异常，看 JsyApiError.serverMsg，对照 docs/jsy-findings.md 业务规则
改了 handler 不生效lantern 用 tsx 跑源码——重启 lantern（重新 spawn mcp-server）即可，不必 build
