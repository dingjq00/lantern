7污染防控P0
问题
多轮 ReAct 中，前一轮的"防御性判断"通过 assistant 消息传染后续轮次。AI 继承犹豫心态。
四种机制：重复调用(5) > 冲突数据(4) > 防御性判断(3) > 截断标记(2)
数据证据
有污染 14 题均 4.46 vs 无污染 26 题均 4.88 → 差距 0.42
cursor2api 解法
converter.ts L556: 正则扫描 assistant 消息，替换拒绝/犹豫痕迹。
AI 不需要看到自己"前世"的犹豫。清洗历史 = 给 AI 信心。
Lantern 适配
去 _truncated → 清洗 assistant 防御性语言 → allResults 去重 → 动态阈值源头治理
预期收益
消除 0.42 分差距 → 3轮题 4.51 → 4.7+

核心认知升级

上下文工程 = 控制 AI 看到什么 + 不给 AI 看什么 + 以什么方式让 AI 看到

Lantern 在"给 AI 看什么"做得好（6层prompt + domain model + data-digest）。但在"不给 AI 看什么"几乎没做 — _truncated 标记、防御性 thought、重复数据全部暴露。cursor2api 的核心教训：AI 的注意力和判断力是有限资源，噪音消耗这些资源。

Playcard 伙伴洞察验证

"4.7→5.0 的瓶颈可能不在架构层，而在多轮对话的上下文污染" — 数据证实：有污染的题低 0.42 分。不是 DeepSeek 能力限制，是我们给了错误的上下文。
